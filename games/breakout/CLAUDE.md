# CLAUDE.md

このファイルは、ブロック崩しプロジェクト(`games/breakout/`)専用のガイドです。リポジトリ全体の共通ルールはルートの `CLAUDE.md` を参照。

## 概要

ブラウザで遊ぶブロック崩しゲーム。素の HTML + バニラ JavaScript で `<canvas>` に描画している。ビルド手順、パッケージマネージャ、リンター、テストはない。画面の文字とコードコメントはすべて日本語なので、新しく追加するユーザー向けの文言も日本語にすること。

## 実行方法

このファイルはゲームのフォルダ `games/breakout/` に置いている。`index.html` をブラウザで直接開くか、リポジトリのルートを静的配信して(例: `npx http-server -c-1 -p 8000` や `python3 -m http.server`)`/games/breakout/` を開く。devcontainer には Node が入っているが、`package.json` はない。

- `http-server` をキャッシュ設定なしで起動すると `max-age=3600` が付き、古い `main.js` がブラウザに残ることがある。`-c-1` でキャッシュを無効にするか、Ctrl+Shift+R で強制再読み込みすること。

## 構成

- `index.html` — ページのレイアウトとスタイル、固定サイズの `<canvas id="game" width="480" height="640">`。CSS でキャンバスを画面に合わせて縮小表示する。`main.js` は通常のスクリプトとして読み込む(モジュールではない)。
- `main.js` — ゲーム全体。上から順に、定数(`設定`)、グローバルな可変状態(`状態`)、レベルとボールの初期化、入力処理(`入力`)、更新(`更新`)、描画(`描画`)、`requestAnimationFrame` のループ、と並んでいる。

ファイル全体にまたがる要点:

- **状態遷移**: グローバルな文字列 `state` ひとつで管理する — `'ready' | 'playing' | 'paused' | 'gameover' | 'clear'`。`launch()`(スペース/Enter/クリック/タップ)が `ready`・`gameover`・`clear` からの遷移を担当し、`P` キーで `playing`/`paused` を切り替える。`update()` と `draw()` はどちらも `state` で分岐するので、状態を追加するときはこの2つと `launch()` を修正すること。
- **座標**: ゲームロジックはすべてキャンバス内部の座標(`W`×`H` = 480×640)を使う。マウス/タッチ入力は `pointerToCanvasX()` で変換し、CSS による縮小を補正している。ブロックの幅は `W` とレイアウト定数から計算する。
- **物理**: 移動はフレーム単位(デルタタイムなし)なので、速度はディスプレイのリフレッシュレートに依存する。すり抜けを防ぐため、ボールは毎フレーム `Math.ceil(currentSpeed() / 3)` 回に分けて移動する。`stepCollisions(ball)` は分割ステップごとに呼ばれ、ボールが落ちたら `'lost'`、全ブロックを壊したら `'clear'`、それ以外は `null` を返す。ブロックとの当たり判定は円と矩形の最近点で行い、めり込みの浅い軸で反射し、1ステップで壊すブロックは最大1個。パドルでの反射角は当たった位置で決まる(最大±60°)。
- **ボールとアイテム**: ボールは `balls` 配列で管理する(マルチボール)。フレームごとのボールのループで落ちたボールに印を付け、すべてのボールがなくなったときだけライフを失う(`loseLife()`)。壊したブロック(`destroyBrick()`)から、`ITEM_TYPES` で定義したアイテムが重み付きランダムで落ちることがある。時間制限のある効果は `effects`(`wide`/`slow`/`pierce`)のフレームカウンタで管理する。ボールの速度は常に `currentSpeed()`(レベル + スロー効果)から求め、スローの開始・終了時は `applySpeedToAll()` で既存のボールの速度を合わせ直す。ライフを失ったときやレベル開始時には、アイテムと効果がリセットされる。
- **保存**: `localStorage` のキー `breakout.highScore`(ハイスコア)と `breakout.sound`(`'on'`/`'off'`、既定は ON)を使う。読み書きは必ず `loadStorage()` / `saveStorage()` を通す(`try/catch` 入りで、保存できない環境でも遊べる)。得点が入るたびに `updateHighScore()` を呼び、超えていればその場で保存して `newRecord` を立てる(ゲームオーバー画面の「ハイスコア更新!」表示に使う)。
- **効果音**: 音声ファイルは使わず、Web Audio API のオシレーターで合成する(`tone()`)。音の種類は `SOUNDS` にまとめ、鳴らすときは必ず `playSound(name)` を使う(`soundOn` が OFF なら何もしない)。自動再生制限のため `AudioContext` は最初に音を鳴らすときに作る。ON/OFF はキャンバス下の `#sound-toggle` ボタンか `M` キーで切り替える(`toggleSound()`)。ボタンはクリック後に `blur()` して、スペースキーでボタンが反応しないようにしている。
- **進行**: 全ブロックを壊すと `level` が1上がり、ボールの速度はレベルごとに 0.7 ずつ上がる(`currentSpeed()`)。スコアとライフは次のレベルに引き継ぐ。ブロックの得点は行で決まる(上の行ほど高い)。

## 実装ルール

- スコアは `localStorage` に保存すること。
- 効果音は ON/OFF を切り替えられるようにすること。
