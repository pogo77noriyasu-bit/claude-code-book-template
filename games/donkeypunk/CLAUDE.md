# CLAUDE.md

このファイルは、ドンキーパンクプロジェクト(`games/donkeypunk/`)専用のガイドです。リポジトリ全体の共通ルールはルートの `CLAUDE.md` を参照。

## 概要

1980 年代アーケード風の固定画面アクション「ドンキーパンク」(α版)。赤いモヒカンのパンクスが斜めの鉄骨とハシゴを登り、ゴリラ警官が転がしてくるビール瓶・ビール缶をよけて、最上段のスキンヘッドガールを救出する。素の HTML + バニラ JavaScript で `<canvas>` に描画する。ゲーム本体にビルド手順はない。画面の文字とコードコメントは日本語。

「鉄骨を転がる障害物をよけて登る」というジャンルの遊び方を参考にしたオリジナル作品。既存作品のキャラクター・画像・音源・ステージの見た目は使わないこと(ドット絵も効果音も BGM も自作)。

**現在は 1 面(斜め鉄骨)・2 面(ライブハウス搬入口)・3 面(解体中のスクワット)・4 面(決戦のやぐら)の 4 面。**2 面は地形・ハシゴ・ベルトコンベア・爆音アンプ・敵「ファイヤースカル」、3 面はリフト 2 種・鉄球・敵「空飛ぶパンクニワトリ」まで。4 面(決戦のやぐら)は初期α版(雑魚敵は怒ったポリスマン。安全ピン 8 本を抜くと鉄骨崩壊 → ゴリラ警官撃墜 → ガール救出 → ROUND CLEAR)。面の並びは 1 → 2 → 3 → 4 → 1(次の周回)。4 面には雑魚敵(怒ったポリスマン)・ボーナスアイテム・釘バット 3 本も入っている。**完成・プレイ確認済み: 1 面・2 面・共通の残機表示。** 2 面はゴリラ警官のバズーカ砲(蛇行ミサイル。周回ごとに強くなる)で十分な難しさになったので、2 面の変則コンベア(不規則な方向転換・速度変化)・上空からの落下爆弾・雑魚ポリスマンによる爆弾の運搬は見送った(ビールケース・ゴリラの往復も入れない)。**3 面も完成・プレイ確認済み**(周回ごとの難しさ・リフトの縦穴での鳥の跳ね上がり・ボーナスアイテム 6 個。釘バットは撤去)。3 面の当初の案(スカル・火花・ゴリラの攻撃)は入れずに完成とした。

## 実行方法

リポジトリのルートを静的配信して(例: `npx http-server -c-1 -p 8000`)`/games/donkeypunk/` を開く。`index.html` を直接開いても動く(ES モジュールを使わず、素の `<script>` を順に読み込んでいるため)。

## テスト

```
cd games/donkeypunk
npm install          # @playwright/test と http-server(初回のみ)
npx playwright install chromium   # ブラウザが無い場合のみ
npm test
```

`playwright.config.js` がリポジトリのルートを 8137 番ポートで配信して `tests/` の `*.spec.js` を実行する(`game.spec.js` は 1 面と共通の動き、`stage2.spec.js` は 2 面、`skull.spec.js` はファイヤースカル、`bazooka.spec.js` は 2 面のゴリラ警官のバズーカ砲と蛇行ミサイル、`stage3.spec.js` は 3 面(リフト・鉄球・パンクニワトリを含む)、`stage3rounds.spec.js` は 3 面の周回ごとのパンクニワトリ(出現数・頻度・火炎攻撃・リフトの縦穴での跳ね上がり)、`stage3prizes.spec.js` は 3 面のボーナスアイテムと釘バットの撤去、`stage4.spec.js` は 4 面、`cops.spec.js` は 4 面の怒ったポリスマン、`prizes.spec.js` は 4 面のボーナスアイテム(仕掛け `prizes` は 3 面でも使う)、`bat4.spec.js` は 4 面の釘バット、`dev.spec.js` は DEV モード(周回・面の指定と無敵)、`music.spec.js` は BGM、`beeredge.spec.js` は 1 面の瓶・缶の画面の端での動き、`stage1rounds.spec.js` は 1 面の周回ごとの難しさ(2 個セット・開幕の連続投げ・連投)、`trash.spec.js` は 1 面の斜め投げのゴミ箱、`jumpcombo.spec.js` は 1 面の複数同時ジャンプの得点、`lives.spec.js` は残機の表示。共通の補助関数は `tests/helpers.js`)。テストは `?test` 付きで開き、`window.__dp`(`js/test-hooks.js`)でループを手動ステップにして、決まったステップ数だけ進めて検証する。キー操作は Playwright の本物のキーボード入力を使う。各テストの最後にコンソールエラーが 0 件であることを確認する。

テスト補助は `?test` が無いと何も公開しない(通常プレイに影響させないこと)。主なもの:

- `snapshot()` / `step(n)` / `setManual(on)`: 状態の取得と手動ステップ(`snapshot()` には `stageIndex` / `stageId` も入る)
- `startStage(i)` / `stageIds()`: 指定の面(0 始まり)から新しいゲームを始める / 面の並び
- `placePlayer` / `placePlayerAir` / `placePlayerLadder` / `spawnHazard` / `setBat` など: 状況を作る
- `sounds()` / `clearSounds()`: 鳴らした効果音の履歴(音 OFF のときは記録されない)
- `music()` / `musicDucked()`: 流れている BGM 名(なければ `null`)と、BGM を下げている最中か
- `conveyors()` / `ampHitbox()` / `setHazardBurns(id)`: コンベアの状態、爆音アンプの当たり判定、障害物を「触れると炎上」にする
- `setSkullsEnabled(on)` / `spawnSkull(girderId, x, { dir, skipSpawn })` / `placeSkullOnLadder` / `clearEnemies()`: ファイヤースカル(`snapshot().enemies` に入る)。`tests/helpers.js` の `startAtStage` は、ゴリラの投下と同じくスカルの自動の出現を止めて始める(`{ skulls: true }` で出す)

## 開発用ショートカット

`localhost` / `127.0.0.1` / ローカルファイルで、URL に `?dev` を付けて開いたときだけ有効(例: `http://localhost:8000/games/donkeypunk/?dev`)。GitHub Pages などの公開先では `?dev` を付けても無効(`DP.devTools.isDevEnvironment` で判定)。有効なときは画面左下に「DEV」と出る。

- **URL で周回・面・無敵を指定**: `?dev&round=3&stage=4&inv=1`(3 周目・4 面・無敵 ON)、`?dev&round=100&stage=2&inv=0`(100 周目・2 面・無敵 OFF)。`round` は 1〜999、`stage` は 1〜面の数、`inv` は 1 = ON / 0 = OFF。省略した項目は 周回 1・面 1・無敵 0、範囲外・数字でない値は無視してその項目は初期値。`round` か `stage` を書くと、開いてすぐその面の READY から始まる(どちらも書かなければ今までどおりタイトルから)。読み取りは `DP.devTools.parseParams`。
- プレイ中に **C** キー: クリアしたことにして、ゴリラ警官の逃走演出を直接始める(クリアの得点も入る)。4 面では、残りの安全ピンをすべて抜いた状態にして崩壊のクリア演出を始める。
- いつでも **1〜9** キー: その面から新しいゲームを始める(1 = 1 面、2 = 2 面、3 = 3 面、4 = 4 面。存在しない面は何もしない)。周回は今の DEV の周回(`g.devRound`。最初は 1 なので、周回を変えなければ今までどおり)。
- いつでも **R** キー: 周回数の入力欄(ブラウザの `prompt`)を出し、入れた周回(1〜999)で今の面から新しいゲームを始める。以後の 1〜9 キーもその周回。正しくない入力・キャンセルは無視。
- いつでも **I** キー: 無敵の ON / OFF(`g.devInvincible`。初期値は OFF)。ミス・面の切り替え・新しいゲーム・次の面のあとも、切り替えるかページを開き直すまで続く(保存はしない)。
- **無敵**: 敵・障害物(ビール・ゴリラ・スカル・爆音アンプ・鉄球・パンクニワトリ・ポリスマン)に触れても、落下しても、ミスにならず残機も減らない。ミスの入口 `game.js` の `killPlayer` だけで止めている(`devInvincible()` = `g.devMode && g.devInvincible`)。`killPlayer` は本当にミスになったときだけ `true` を返し、呼び出し側は `true` のときだけそのステップの残りの処理をやめる(無敵中も、そのステップの飛び越えの得点・ゴリラとの判定・ボーナスの減少・クリアの判定が飛ばされない)。仕掛けからの `ctx.killPlayer` も同じ。
  - 落下: 着地してから高すぎたと分かったときは、そのまま立っている。下に足場がなく画面の下へ出たとき(3 面の縦穴など)は、最後に立っていた安全な足場(リフト以外。`g.devSafe`。面を組み立てるたびに忘れる)へ戻す。その鉄骨がなくなっていたら同じ床で x を含む鉄骨、それもなければスタート位置(`recoverFromFall`)。戻った回数はテスト補助の `snapshot().dev.recovered`。
  - 得点・釘バット・ボーナスアイテム・安全ピン・クリア・各演出・ボーナスの減り方は通常どおり。
- **ハイスコア**: DEV モードのあいだ(無敵かどうかに関係なく)はハイスコアを保存せず、画面の HI も変えない(`saveHiScore`)。得点の計算は通常どおり。
- **画面**: 左下に「DEV R3 ST4  C:クリア 1〜4:面 R:周回 I:無敵」(今の周回と面)。無敵中は右下に「INVINCIBLE」(15 ステップごとに黄と赤で点滅。消えはしない)。
- **通常プレイでは絶対に有効にならない**: `devMode` / `devRound` / `devInvincible` は `DP.devTools.install` の中でだけ設定し、`install` は開発環境で `?dev` のときしか動かない(URL に `inv=1` などを書いても、?dev がない・公開先なら読まない)。さらに `killPlayer` 側でも `devMode` を確かめる(二重の守り)。
- テスト `tests/dev.spec.js`(D1〜D9 = URL の指定と省略・範囲外 / 通常プレイと公開先では無効・二重の守り / I キーと INVINCIBLE の表示 / 7 種類の敵・障害物で無敵 ON はミスなし・OFF はミス / 落下: 穴に落ちても立つ・画面の下から足場へ戻る・リフトは戻り先にしない / 得点・ピン・アイテム・釘バット・飛び越え・ボーナス・クリアは通常どおり / ハイスコアを保存しない / R キーと 1〜4 キーと C キー / 設定が続く)。テスト補助 `snapshot().dev`(`mode` / `invincible` / `round` / `recovered`)・`snapshot().hiScore`。

## 設計上の要点

### 基本

- **面ごとの仕掛け**: すべての面で共通の処理(主人公・釘バット・障害物の移動・当たり判定・クリアと逃走演出)は `game.js` に置き、面ごとに違う仕掛けだけを `js/mechanics.js` に登録して、ステージデータの `mechanics: [...]` で選ぶ。1 面は `['beerThrow']`(ゴリラ警官のビール投下。`boss.throwX` / `throwInterval` / `canRatio` を使う)。仕掛けは主人公と釘バットの処理のあと・障害物の移動の前に呼ばれる。ゴリラを動かす仕掛けがない面では、ゴリラは待機アニメだけ(`enemies.idleBoss`)。
- **面の並び**: `DP.stages` に登録した順(`index.html` の読み込み順)。1 面 → 2 面 → 3 面 → 4 面 → 1 面(`round` +1)… とくり返す。ステージデータに `devOnly: true` を書いた開発中の面は `game.js` の `nextStage` が飛ばす(開発用ショートカットとテスト補助の `startStage` からだけ始められる。今はどの面にも書いていない)。
- **鉄骨の色**: ステージデータの `girderColors: { body, top, bottom }` で面ごとに変えられる(指定がなければ 1 面のピンク)。
- **鉄骨の種類**: 鉄骨に `kind: 'conveyor'` と `conveyor: { dir, reverseEvery }` を書くとベルトコンベアになる(2 面。動きは仕掛け `conveyors`)。書かなければ普通の鉄骨(色は `girderColors`)。
- **座標**: プレイヤーと障害物の `x` は中心、`y` は足元(下端)。鉄骨は線分 `(x1,y1)-(x2,y2)` で、`y` は上面。厚みは `GIRDER_THICKNESS`(8)。
- **時間**: 物理は 1/60 秒の固定ステップ。速度は px/ステップ。描画は requestAnimationFrame。
- **状態遷移**: `'title' | 'ready' | 'playing' | 'escape' | 'collapse'(4 面のクリア演出)| 'clear' | 'intermission'(1〜3 面のあとの面間演出)| 'dying' | 'gameover'`。`game.data.timer` が状態ごとの経過ステップ。
- **着地と天井**: 着地は「前のステップで上面より上、今のステップで上面以下」を調べる連続判定(`findLanding`)で、速くてもすり抜けない。上昇中は頭が鉄骨の下面を通過したら止める(`findCeiling`)ので、下から突き抜けない。

### 主人公

- **描画と当たり判定は別**: ドット絵は 40x40px(20x20 ドット)。モヒカンは額から頭頂部・後頭部を通って首の付け根まで続く大きな扇形(半円)で、後頭部へ広げるため元の 12 幅の体を左右 4 ドットずつ広げている(左右同じだけ広げるので反転しても体の位置は変わらない)。当たり判定は `config.player`(幅 14 × 高さ 26px)で顔から下の体だけを覆い、モヒカンは含めない(モヒカンだけにビールが触れてもミスにならない)。ドット絵を変えても当たり判定は変わらない。
- **ジャンプと落下**: ジャンプの横速度は踏み切りで決まる。空中に出た高さから `fatalFall`(48px)を超えて下へ落ちるとミス。測る基準は `player.fallFromY`: 歩いて踏み外したときはその足場の高さ、**ジャンプしたときは踏み切った高さ**(空中の最高点ではない)。リフトの板に空中から乗ったとき(`landOn`)も同じ。
  - 以前は最高点(踏み切りの約 38px 上)から測っていたため、跳んで降りられるのは約 10px 低い所までだった。3 面の飛び石を増やすために変更した(移動速度・ジャンプ力は変えていない)。変更時に 1 面 115 通り・2 面 25 通りの跳び降りを調べ、結果が変わるものは 0 件(1 面の段差は最小 52.3px = g5 の右端 → g4 で、48px との余裕は 4.3px しかない。1 面の段の間隔を狭めるときは注意。2 面は 78px 以上)。テスト 45(1 面)/ S6b(2 面)/ L18(3 面)。

### ハシゴ

- **通常のハシゴ**: つかめる範囲(`ladderGrab` = 6px)にいるときだけ昇降でき、昇降中は左右移動・ジャンプ不可。上りきると上の段、下りきると下の段に立つ。
- **安全地帯**: 障害物はハシゴの上を通ると降りることがあるが、プレイヤーがそのハシゴにつかまっているときと、**そのハシゴの下で待っているとき**(下の段の上で、ハシゴの中心から左右 `hazard.ladderSafeX` 16px 以内に立っている・その場で跳んでいる。`hazards.playerUnderLadder`)は降りずに通過する(ハシゴ上では左右によけられないため。ハシゴの下は降ってくる瓶を気にせず待てる場所)。ほかのハシゴでは今までどおり 25% で降りる。無敵ではなく、下の段を転がってくる瓶・すでに降りている瓶の下へ自分から入ったときは当たる。16px は、降りてくる瓶(幅 18)と瓶用の当たり判定(幅 12)が横に重なる範囲(中心の差 15px 未満)を覆う幅。頭(当たり判定の上端)が上の段の上面より下なら頭上をやり過ごせる(モヒカンは上の段の上へ突き出してよい)。
- **切れたハシゴ**(ステージデータで `broken: true`): 下からつかまって `climbTopY`(上の段の上面 + `config.brokenLadder.headroom` 52px。モヒカンの先まで上の段に届かない高さ)まで登れるが、そこで止まり上の段へは移れない。↓ で下の段へ降りられる。上の段からはつかまれない。見た目は下の部分と、上の段からぶら下がる切れ端(`stub` 24px)の 2 本で描く。障害物は切れたハシゴも降りる(安全地帯の判定も同じ)。正規のハシゴの番号を変えないよう、ステージデータの最後に足している。正規のハシゴだけでゴールまで行けるルートを必ず残すこと(テスト 30 で確認)。
- **逃走用ハシゴ**(ステージデータの `escape.ladders`): ゴリラとガールの間に立つ、g5 から画面の最上部までの 2 本。クリア後の逃走演出で使う飾りなので `level.ladders` には入れない(プレイヤーはつかめず、障害物も降りない。ハシゴの番号にも影響しない)。

### 釘バット(ステージデータの `items`)

- **置き場所**: 鉄骨から `config.bat.itemFloat`(44px)浮かせて置く。立っているときのモヒカンの先(40px)にも届かず、ジャンプ(最高点 約 40px)して空中で触れたときだけ拾う。1〜3 面は、通り道で拾わされないよう、ハシゴからハシゴへの通り道から外れた鉄骨の端に置いている。4 面は逆に、難しさを調整する武器として通り道の真上に置く(下の「4 面」の「釘バット」)。
- **取得判定**: 大きさ(`itemWidth`/`itemHeight` = 36x18)はドット絵 `batSide` の大きさ × `PIXEL` と同じにして、見た目と一致させている(描画で揺らさないこと)。
- **攻撃**: 拾うと `config.bat.duration`(600 ステップ = 10 秒)の間、`swingHalf`(8 ステップ)ごとに頭上(`up`)と前の足元(`down`)へ交互に振る(`player.batPhase` / `player.batHitbox`)。攻撃範囲に入ったビールは体との当たり判定より先に割れて 300 点(`score.smash`)。前から来るビールは必ず届く広さだが、背中側から来たものには当たる。
- **制限**: 持っている間はジャンプとハシゴの昇降ができない(左右移動はそのまま)。
- **残り時間**: 頭上のバーと HUD の `BAT` バーで表示し、残り `warnAt`(3 秒)で点滅と警告音。

### ゲーム進行

- **ミス**: `game.js` の `killPlayer(reason)` で主人公を `'dead'` にして `'dying'` へ。理由は `'fall'`(落下)/ `'hazard'`(障害物)/ `'boss'`(ゴリラ)/ `'burn'`(炎上)。すでにミスしているときは何もしないので、残機が二重に減らない。演出中は `updatePlaying` を呼ばないので操作・移動・コンベア・当たり判定は止まる。演出の長さは `config.timing.dyingByReason`(炎上は 60 ステップ)、書いていない理由は `timing.dying`(120 ステップ)。演出が終わったら 1 回だけ残機を減らす。
  - ふつうのミスは、くるくる回って倒れる演出。炎上は、その場で止まった主人公を黄・オレンジ・赤の炎が包み、後半は黒こげになる(`renderer.js` の `drawBurning`)。
  - 炎上の入口は使い回せる: 仕掛けからは `ctx.killPlayer('burn')`、障害物は `burns: true` を付けると触れたとき炎上になる(将来のファイヤースカル用)。
- **残機の表示**: 画面左上の残機(モヒカンの頭アイコン)は、プレイ中の 1 人を除いた予備の数 `max(0, 残機 - 1)` だけ描く(開始時は 2 人、最後の 1 人をプレイしているときは 0 人。全 4 面・全周回。`renderer.js` の `drawHud`)。内部の残機 `g.lives`(開始時 `config.lives` = 3)・ミス・ゲームオーバーの判定は変えていない(表示だけ。エクステンドは今はない)。以前は残機の数そのもの(開始時 3 人)を描いていた。テスト `tests/lives.spec.js`(L1 = 全 4 面・1 周目と 2 周目で、開始 2 人 → 1 回ミス 1 人 → 2 回ミス 0 人 → 3 回目でゲームオーバー / L2 = タイトルから始めた READY の間も 2 人)。
- **ミス後**: ステージを組み立て直し、開始位置(`playerStart`)から再開する。障害物は消え、釘バットは手放してアイテムは元の場所に戻る。
- **クリア時の逃走演出**(`'escape'`): ガールに触れると得点を足して `'escape'` に入る。残っているビールは消し、釘バットは手放す(BGM もその場で止まる)。演出中は `updatePlaying` を呼ばないので、操作・障害物・当たり判定・ボーナス減少は止まり、ミスにならない。
  - 段階: `walk`(ゴリラがガールの下 `grabX` へ歩く)→ `reach`(腕を振り上げ、ガールを足場の端 `girlEdgeX` へ引き寄せる)→ `lift`(担ぎ上げる)→ `struggle`(ガールがジタバタ)→ `carry`(逃走用ハシゴの真ん中へ歩く)→ `climb`(背中向きで左右の手を交互に 2 本のハシゴへかけて登る)→ ゴリラの足元まで画面の上へ出たら `'clear'`。速さ・長さは `config.escape`。
  - 演出後は `boss.gone` / `heroine.gone` が立ち、クリア表示ではハートも出さない。次のステージでは元に戻る。
- **クリア後**: ENTER は使わず自動で進む。1〜3 面はクリア表示「Oi! Oi! Oi!」を `timing.clearAuto`(180 ステップ = 3 秒)出してから面間演出(下の「面間演出」)→ 次の面の READY。4 面はエンディングのあとの「ROUND CLEAR」(花火・幸せな BGM が続く)を `timing.roundClearAuto`(300 ステップ = 5 秒)出してから次の周回の 1 面。クリア表示中に ENTER を押しても早まらない。最後のステージの次は 1 面に戻り `round` が +1(速度・投下頻度が上がる)。得点・残機は引き継ぐ。

### 面間演出(`js/intermission.js`、状態 `'intermission'`。長さ・間隔は `config.intermission`)

1〜3 面のクリア表示が終わると(自動。ENTER なし)、次の面を組み立てる前に「警察官がやぐらを積み上げる」演出が自動で流れ、終わると次の面の READY になる(`game.js` の `nextStage` → `updateIntermission` → `setupStage`)。参考にしたのは「面の合間に建物が高くなっていく様子を見せる」という考え方だけで、配置・高さの表示・決まり文句・キャラクターは使わないオリジナルの演出。

- **入る場面**: 1→2 面・2→3 面・3→4 面だけ(`DP.intermission.has(from, to)`)。4 面のあと(次の周回の 1 面)は入らず、4 面のエンディング(青空・教会・花火)のまま。周回で分岐しないので、1 周目も 2 周目以降も同じ演出・同じ長さ(乱数も使わない)。

### 4 面「決戦のやぐら」(初期α版: 配置・ピンを抜く処理・崩壊のクリア演出。雑魚敵なし)

野外フェスの鉄骨やぐら。各段の床を留める巨大な安全ピン 8 本をすべて抜くと、やぐらが崩れてゴリラ警官が落ちる最終決戦の面(予定)。参考にしたのは「ピンを抜くと足場が消え、全部抜くとボスが落ちる」という遊び方だけで、原作の配置(段の数・左右対称のリベットの列)・見た目・敵・アイテムは使わない。

- **開発の手順**(各段階でユーザーがプレイして承認してから次へ): 第 1 段階 = 鉄骨・ハシゴ・ピン 8 本・ゴリラ・ガールの配置 / 第 2 段階 = ピンを抜く処理・足場が消える処理・得点 / 第 3 段階 = 崩壊・拳銃乱射・ゴリラの落下・ガール救出・ROUND CLEAR・周回(`devOnly` を外して 1 → 2 → 3 → 4 → 1 にした)。雑魚敵・敵 AI・釘バット・ボーナス品・周回ごとの難しさは後回し。
- **決まっているルール**: ピンは 8 本。抜くとその部分(幅 24px)の床が消える。**ハシゴは切れない**(ハシゴはピンの穴の端から 20px 以上離して置く)。抜く順番で移動ルートが変わる。どの順番でも詰まないことを、ピンの状態(2 の 8 乗 = 256 通り)と実際の移動経路で確かめる(第 2 段階)。8 本すべて抜くと崩壊してゴリラが落ち、ガール救出・クリア演出のあと周回 +1 で 1 面へ戻る。
- **配置**(`js/stages/stage4.js`): 地面 f0(y540、x 0〜480。スタート x=30)/ F1(y445、x 16〜464)/ F2(y350、x 32〜448)/ F3(y255、x 48〜432)/ F4(y160、x 16〜464。ゴリラ警官 x=240)/ ガールの足場 top(y82、x 176〜304。ガール x=210)。段の間隔は 95px(2 面と同じ)。床は各段 1 枚。

  - `audio.js` の `SONGS.main` が `DP.music.events()` の音を予約して鳴らす(釘バットの BGM と同じ予約方式・ダッキング・M キーの扱い)。BGM 全体の音量 `gain: 0.75` で効果音より控えめ。タブが裏に回ってタイマーが遅れても、過ぎた音はまとめて鳴らさず今の時刻から続ける。
  - `updateMusic()`: READY(ゲーム開始・各面の開始・ミス後)とプレイ中は `'main'`、釘バット所持中は `'bat'` を優先し、時間切れで `'main'` に戻る(頭から)。ミス(dying)・逃走演出・クリア・ゲームオーバー・タイトルでは止める。面の切り替えでは逃走演出で一度止まるので 2 曲が重ならない。足音は今までどおり(釘バット使用中以外は鳴る)。
  - ブラウザの音声再生の制限: 最初のキー入力・クリック・タッチで `AudioContext` を作って再開する(`audio.js` の `unlock`)。
  - テストは `tests/music.spec.js`(M1〜M9)。テスト補助: `musicActive()`(流れている BGM の数)/ `audioState()` / `recordMusicSteps()`・`musicSteps()`・`seekMusic(step)`(ループのつなぎ目の確認)。
- **4 面のエンディングの BGM**(`'happy'`。オリジナル曲。曲データは `js/music.js` の `SONGS.happy`、鳴らすのは `audio.js` の `SONGS.happy` で通常の BGM と同じ仕組み): C メジャー・132 BPM・8 小節ループ。C → F → G → C / Am → F → G → C の明るい進行に、跳ねるように上がる 25% 矩形波のメロディー、16 分の分散和音、オクターブのベース、軽い 8 ビート。`updateMusic()` が「4 面のクリア演出(またはそのあとのクリア表示)でハートが出ている」ときに流す。ハートの前(崩壊・乱射・落下)は BGM なし。テスト R27・R28、M(面を進める)テストでもクリア中の BGM を確かめる。
- **釘バットの BGM**(オリジナル曲 `BAT_SONG`: テンポ 168、Em→C→D→B の 4 小節ループ。矩形波メロディー + 三角波ベース + 雑音スネア): `game.js` の `updateMusic()` が毎ステップの最後と逃走演出の開始時に「プレイ中かつバット所持中」かを見て `DP.audio.setMusic('bat' | null)` を呼ぶので、時間切れ・ミス・クリアで自動的に止まる。音 OFF の間は流さず、ON に戻したときまだ所持中なら再開する。少し先まで音を予約しておき 40ms ごとに続きを足す方式で、止めるときは BGM 専用の GainNode ごと切り離す。取得音・破壊音・警告音・終了音は BGM と同時に鳴らす。
- **釘バットの破壊音** `smash`(「ビュイ～～ン!」。`zap`): 約 0.5 秒で 1760Hz → 140Hz へ指数カーブで下げる矩形波 + 1 オクターブ下の三角波に、22Hz のビブラートをかける。BGM 中でも聞こえるよう大きめに鳴らし、鳴っている間は BGM の音量を 3 割に下げる(`duckMusic`)。得点表示と同じステップで鳴る。
- **逃走演出の音**: 歩き・足踏みのたびに足音(`bossStep` / `bossStep2`。矩形波を 180Hz → 60Hz へ急降下 + 雑音)、担ぎ上げる瞬間に悲鳴(`scream`)、手をかけ替えるたびに登る音(`climb`。登った段数ぶん半音ずつ高くなる)、終わったらクリアジングル。
- **3 面のパンクニワトリの火炎**: 噴き始めに `birdFire`(「ボォォッ」。0.45 秒の粗い雑音 + 520Hz → 160Hz へうなりながら下がるのこぎり波 + 高い「シュッ」)。
- **2 面のバズーカ砲の音**: 装填 `bazookaReady`(「ガチャッ」。高い矩形波 2 つ + 小さな雑音)/ 発射 `bazookaFire`(「ドシュッ」。220Hz → 55Hz の矩形波 + 雑音 + 1600Hz → 420Hz ののこぎり波)/ 釘バットでミサイルを壊した `missileBoom`(「ズドドーン!」。高い炸裂音 → 700Hz → 35Hz の長い矩形波と雑音 → 0.16 秒後にもう 1 回の爆発。通常の破壊音 `smash` より長く大きく、約 1.1 秒 BGM を下げる)。
- **低い音の注意**: ノート PC などの小さなスピーカーは約 150Hz 以下をほとんど鳴らせない。低い音を作るときは、倍音の多い矩形波にしたり高めの成分から始めたりして、聞こえる成分を含めること。

## ステージを追加するとき

1. `js/stages/stage3.js` などを作り、`DP.stages.push({...})` で登録する(`index.html` の読み込みも追加)。面の仕掛けが必要なら `js/mechanics.js` に登録し、ステージデータの `mechanics` に名前を書く。
2. ベルトコンベア・エレベーター・リベットなど新しい地形は、ステージデータ(鉄骨の `kind` や新しい種類のデータ)に書き、`geometry.buildLevel` で実行時オブジェクトにして、毎ステップの更新は `js/mechanics.js` の仕掛けとして登録する(`game.js` に面ごとの処理を直接書かない)。プレイヤーや障害物の着地判定は `geometry` / `physics` にまとめる。
3. 周回の難易度は `game.js` の `difficulty()` で調整する。

## 実装ルール

- ハイスコアは `localStorage` のキー `pachiDonkey.highScore`、音の設定は `pachiDonkey.sound`(`'on'`/`'off'`)。プロジェクト名変更前の名前だが、変えると保存済みのデータが消えるのでそのままにする。
- ドット絵の見た目を変えても当たり判定は変わらない。見た目に合わせた高さの数値(`brokenLadder.headroom`、`bat.itemFloat` など)は、主人公のドット絵の高さを変えたら見直すこと。
