# CLAUDE.md

このファイルは、ドンキーパンクプロジェクト(`games/donkeypunk/`)専用のガイドです。リポジトリ全体の共通ルールはルートの `CLAUDE.md` を参照。

## 概要

1980 年代アーケード風の固定画面アクション「ドンキーパンク」(α版)。赤いモヒカンのパンクスが斜めの鉄骨とハシゴを登り、ゴリラ警官が転がしてくるビール瓶・ビール缶をよけて、最上段のスキンヘッドガールを救出する。素の HTML + バニラ JavaScript で `<canvas>` に描画する。ゲーム本体にビルド手順はない。画面の文字とコードコメントは日本語。

「鉄骨を転がる障害物をよけて登る」というジャンルの遊び方を参考にしたオリジナル作品。既存作品のキャラクター・画像・音源・ステージの見た目は使わないこと(ドット絵も効果音も BGM も自作)。

**現在は 1 面(斜め鉄骨)と 2 面(ライブハウス搬入口・制作中)。** 2 面は地形・ハシゴ・面の遷移・ベルトコンベアの動き・爆音アンプ(見た目と、触れると炎上するミス)・敵「ファイヤースカル」まで。ビールケース・ゴリラの往復は今後。3 面(エレベーター)、4 面(リベット)、4 面クリア後の難易度アップ周回は今後の予定。

## 実行方法

リポジトリのルートを静的配信して(例: `npx http-server -c-1 -p 8000`)`/games/donkeypunk/` を開く。`index.html` を直接開いても動く(ES モジュールを使わず、素の `<script>` を順に読み込んでいるため)。

## 操作(PC キーボード優先。タッチ操作は未対応)

- ← →: 移動 / ↑ ↓: ハシゴ昇降(ハシゴの位置でだけ) / SPACE: ジャンプ / ENTER: 開始・再挑戦 / M: 音 ON/OFF

## テスト

```
cd games/donkeypunk
npm install          # @playwright/test と http-server(初回のみ)
npx playwright install chromium   # ブラウザが無い場合のみ
npm test
```

`playwright.config.js` がリポジトリのルートを 8137 番ポートで配信して `tests/` の `*.spec.js` を実行する(`game.spec.js` は 1 面と共通の動き、`stage2.spec.js` は 2 面、`skull.spec.js` はファイヤースカル。共通の補助関数は `tests/helpers.js`)。テストは `?test` 付きで開き、`window.__dp`(`js/test-hooks.js`)でループを手動ステップにして、決まったステップ数だけ進めて検証する。キー操作は Playwright の本物のキーボード入力を使う。各テストの最後にコンソールエラーが 0 件であることを確認する。

テスト補助は `?test` が無いと何も公開しない(通常プレイに影響させないこと)。主なもの:

- `snapshot()` / `step(n)` / `setManual(on)`: 状態の取得と手動ステップ(`snapshot()` には `stageIndex` / `stageId` も入る)
- `startStage(i)` / `stageIds()`: 指定の面(0 始まり)から新しいゲームを始める / 面の並び
- `placePlayer` / `placePlayerAir` / `placePlayerLadder` / `spawnHazard` / `setBat` など: 状況を作る
- `sounds()` / `clearSounds()`: 鳴らした効果音の履歴(音 OFF のときは記録されない)
- `music()` / `musicDucked()`: 流れている BGM 名(なければ `null`)と、BGM を下げている最中か
- `conveyors()` / `ampHitbox()` / `setHazardBurns(id)`: コンベアの状態、爆音アンプの当たり判定、障害物を「触れると炎上」にする
- `setSkullsEnabled(on)` / `spawnSkull(girderId, x, { dir, skipSpawn })` / `placeSkullOnLadder` / `clearEnemies()`: ファイヤースカル(`snapshot().enemies` に入る)。`tests/helpers.js` の `startAtStage` は、ゴリラの投下と同じくスカルの自動の出現を止めて始める(`{ skulls: true }` で出す)

## 開発用ショートカット

`localhost` / `127.0.0.1` / ローカルファイルで、URL に `?dev` を付けて開いたときだけ有効(例: `http://localhost:8000/games/donkeypunk/?dev`)。GitHub Pages などの公開先では `?dev` を付けても無効(`DP.devTools.isDevEnvironment` で判定)。有効なときは画面左下に「DEV」と出る。

- プレイ中に **C** キー: クリアしたことにして、ゴリラ警官の逃走演出を直接始める(クリアの得点も入る)。
- いつでも **1〜9** キー: その面から新しいゲームを始める(1 = 1 面、2 = 2 面。存在しない面は何もしない)。

## 設計上の要点

### 基本

- **面ごとの仕掛け**: すべての面で共通の処理(主人公・釘バット・障害物の移動・当たり判定・クリアと逃走演出)は `game.js` に置き、面ごとに違う仕掛けだけを `js/mechanics.js` に登録して、ステージデータの `mechanics: [...]` で選ぶ。1 面は `['beerThrow']`(ゴリラ警官のビール投下。`boss.throwX` / `throwInterval` / `canRatio` を使う)。仕掛けは主人公と釘バットの処理のあと・障害物の移動の前に呼ばれる。ゴリラを動かす仕掛けがない面では、ゴリラは待機アニメだけ(`enemies.idleBoss`)。
- **面の並び**: `DP.stages` に登録した順(`index.html` の読み込み順)。1 面 → 2 面 → 1 面(`round` +1)… とくり返す。
- **鉄骨の色**: ステージデータの `girderColors: { body, top, bottom }` で面ごとに変えられる(指定がなければ 1 面のピンク)。
- **鉄骨の種類**: 鉄骨に `kind: 'conveyor'` と `conveyor: { dir, reverseEvery }` を書くとベルトコンベアになる(2 面。動きは仕掛け `conveyors`)。書かなければ普通の鉄骨(色は `girderColors`)。
- **座標**: プレイヤーと障害物の `x` は中心、`y` は足元(下端)。鉄骨は線分 `(x1,y1)-(x2,y2)` で、`y` は上面。厚みは `GIRDER_THICKNESS`(8)。
- **時間**: 物理は 1/60 秒の固定ステップ。速度は px/ステップ。描画は requestAnimationFrame。
- **状態遷移**: `'title' | 'ready' | 'playing' | 'escape' | 'clear' | 'dying' | 'gameover'`。`game.data.timer` が状態ごとの経過ステップ。
- **着地と天井**: 着地は「前のステップで上面より上、今のステップで上面以下」を調べる連続判定(`findLanding`)で、速くてもすり抜けない。上昇中は頭が鉄骨の下面を通過したら止める(`findCeiling`)ので、下から突き抜けない。

### 主人公

- **描画と当たり判定は別**: ドット絵は 40x40px(20x20 ドット)。モヒカンは額から頭頂部・後頭部を通って首の付け根まで続く大きな扇形(半円)で、後頭部へ広げるため元の 12 幅の体を左右 4 ドットずつ広げている(左右同じだけ広げるので反転しても体の位置は変わらない)。当たり判定は `config.player`(幅 14 × 高さ 26px)で顔から下の体だけを覆い、モヒカンは含めない(モヒカンだけにビールが触れてもミスにならない)。ドット絵を変えても当たり判定は変わらない。
- **ジャンプと落下**: ジャンプの横速度は踏み切りで決まる。高さ `fatalFall`(48px)以上から落ちるとミス(通常のジャンプは約 40px なので安全)。
- **障害物との当たり判定**: ジャンプ中も毎ステップ行う。真下を飛び越えると 100 点。

### ハシゴ

- **通常のハシゴ**: つかめる範囲(`ladderGrab` = 6px)にいるときだけ昇降でき、昇降中は左右移動・ジャンプ不可。上りきると上の段、下りきると下の段に立つ。
- **安全地帯**: 障害物はハシゴの上を通ると降りることがあるが、プレイヤーがそのハシゴにつかまっているときは降りずに通過する(ハシゴ上では左右によけられないため)。頭(当たり判定の上端)が上の段の上面より下なら頭上をやり過ごせる(モヒカンは上の段の上へ突き出してよい)。
- **切れたハシゴ**(ステージデータで `broken: true`): 下からつかまって `climbTopY`(上の段の上面 + `config.brokenLadder.headroom` 52px。モヒカンの先まで上の段に届かない高さ)まで登れるが、そこで止まり上の段へは移れない。↓ で下の段へ降りられる。上の段からはつかまれない。見た目は下の部分と、上の段からぶら下がる切れ端(`stub` 24px)の 2 本で描く。障害物は切れたハシゴも降りる(安全地帯の判定も同じ)。正規のハシゴの番号を変えないよう、ステージデータの最後に足している。正規のハシゴだけでゴールまで行けるルートを必ず残すこと(テスト 30 で確認)。
- **逃走用ハシゴ**(ステージデータの `escape.ladders`): ゴリラとガールの間に立つ、g5 から画面の最上部までの 2 本。クリア後の逃走演出で使う飾りなので `level.ladders` には入れない(プレイヤーはつかめず、障害物も降りない。ハシゴの番号にも影響しない)。

### 障害物

- 鉄骨の低い側(`downhill`)へ転がり、端から落ちて下の段で 1 回跳ね、その段の低い側へ向きを変える。最下段の左端から画面外へ出たら消える。ビール瓶は細長く速い、缶は丸くて遅い。
- ハシゴの上を通ると `ladderChance`(25%)で降りる(`noHazard` のハシゴは除く。安全地帯は上の「ハシゴ」を参照)。判定の乱数はプレイヤーの位置に関係なく 1 回消費する。

### 釘バット(ステージデータの `items`)

- **置き場所**: 鉄骨から `config.bat.itemFloat`(44px)浮かせて置く。立っているときのモヒカンの先(40px)にも届かず、ジャンプ(最高点 約 40px)して空中で触れたときだけ拾う。通り道で拾わされないよう、ハシゴからハシゴへの通り道から外れた鉄骨の端に置いている。
- **取得判定**: 大きさ(`itemWidth`/`itemHeight` = 36x18)はドット絵 `batSide` の大きさ × `PIXEL` と同じにして、見た目と一致させている(描画で揺らさないこと)。
- **攻撃**: 拾うと `config.bat.duration`(600 ステップ = 10 秒)の間、`swingHalf`(8 ステップ)ごとに頭上(`up`)と前の足元(`down`)へ交互に振る(`player.batPhase` / `player.batHitbox`)。攻撃範囲に入ったビールは体との当たり判定より先に割れて 300 点(`score.smash`)。前から来るビールは必ず届く広さだが、背中側から来たものには当たる。
- **制限**: 持っている間はジャンプとハシゴの昇降ができない(左右移動はそのまま)。
- **残り時間**: 頭上のバーと HUD の `BAT` バーで表示し、残り `warnAt`(3 秒)で点滅と警告音。

### ゲーム進行

- **ミス**: `game.js` の `killPlayer(reason)` で主人公を `'dead'` にして `'dying'` へ。理由は `'fall'`(落下)/ `'hazard'`(障害物)/ `'boss'`(ゴリラ)/ `'burn'`(炎上)。すでにミスしているときは何もしないので、残機が二重に減らない。演出中は `updatePlaying` を呼ばないので操作・移動・コンベア・当たり判定は止まる。演出の長さは `config.timing.dyingByReason`(炎上は 60 ステップ)、書いていない理由は `timing.dying`(120 ステップ)。演出が終わったら 1 回だけ残機を減らす。
  - ふつうのミスは、くるくる回って倒れる演出。炎上は、その場で止まった主人公を黄・オレンジ・赤の炎が包み、後半は黒こげになる(`renderer.js` の `drawBurning`)。
  - 炎上の入口は使い回せる: 仕掛けからは `ctx.killPlayer('burn')`、障害物は `burns: true` を付けると触れたとき炎上になる(将来のファイヤースカル用)。
- **ミス後**: ステージを組み立て直し、開始位置(`playerStart`)から再開する。障害物は消え、釘バットは手放してアイテムは元の場所に戻る。
- **クリア時の逃走演出**(`'escape'`): ガールに触れると得点を足して `'escape'` に入る。残っているビールは消し、釘バットは手放す(BGM もその場で止まる)。演出中は `updatePlaying` を呼ばないので、操作・障害物・当たり判定・ボーナス減少は止まり、ミスにならない。
  - 段階: `walk`(ゴリラがガールの下 `grabX` へ歩く)→ `reach`(腕を振り上げ、ガールを足場の端 `girlEdgeX` へ引き寄せる)→ `lift`(担ぎ上げる)→ `struggle`(ガールがジタバタ)→ `carry`(逃走用ハシゴの真ん中へ歩く)→ `climb`(背中向きで左右の手を交互に 2 本のハシゴへかけて登る)→ ゴリラの足元まで画面の上へ出たら `'clear'`。速さ・長さは `config.escape`。
  - 演出後は `boss.gone` / `heroine.gone` が立ち、クリア表示ではハートも出さない。次のステージでは元に戻る。
- **クリア後**: ENTER で次のステージへ。最後のステージの次は 1 面に戻り `round` が +1(速度・投下頻度が上がる)。

### 2 面「ライブハウス搬入口」

- 床(y=540)→ 下段コンベア(445。画面の端から端まで)→ 中段の足場(350。茶色の鉄骨 `mid`。画面の左端から右端まで 1 枚で、すき間なし。端から落ちるストレスを減らすため)→ 中段コンベア(255。中央の x 220〜260 で左右に分かれ、そこに爆音アンプ。外側の端は画面の端まで)→ 最上段コンベア(160。ゴリラ警官。画面の端から端まで)→ ガールの足場(82。1 面と同じ位置)。段の間隔は約 95px。画面の左右の端で落ちないよう、床・下段・中段の足場・中段左右(外側)・最上段は画面の端(x 0 / 480)まで届いている。主人公は画面の端で止まり、コンベアに押されても足場の上に立ったまま(テスト S6・C3・C7)。落ちられるのはガールの足場の端だけ。コンベアの滑車は画面からはみ出さないよう内側(x 6 / 474)に寄せて描く。
- **ハシゴはジグザグ**(9 本): 左右どちらか片側だけでは最上段まで登れず、各段でコンベアや足場を横断させる(テスト Z1):
  - 床を右へ(x=440 のハシゴだけ)→ 下段コンベアを左へ(x=64 か 200 で中段の足場へ)→ 中段の足場を横へ → 中段左コンベア(x=96)なら右へ最上段(x=200)、中段右コンベア(x=296 / 384)なら流れに逆らって右へ最上段(x=448)→ 最上段を歩いてガール(x=288)
  - 中段の足場が 1 枚なので、下段からの 2 本 × 中段コンベアへの 3 本 = 6 通りの登り方がある。どれも途中で 2 回以上左右に折り返す。
  - 最短クリアは約 19.4 秒(x=200 → x=96 のルート。敵なし・最短の操作。テスト Z2 で最速ルートが 18〜22 秒、6 通りすべてで登りきれることを確認)。ほかのルートは約 19.7〜25.3 秒。
- 最上段へのハシゴは x=200 と 448 で、どちらもゴリラ警官(x=56)より右に出るので、ガールの足場へのハシゴ(x=288)まで歩いても道をふさがれない(テスト S2)。2 本のルートを実際のキー操作で確認している(S3・S4)。
- 仕掛けは `['conveyors', 'amp', 'fireSkulls']`。ゴリラは立っているだけでビールを投げない。逃走演出は 1 面と同じ配置で動く。
- **爆音アンプ**(仕掛け `amp`): 本体と炎に触れると炎上のミス。当たり判定は `config.amp`(幅 32 × 高さ 58px。本体より左右 2px ずつ小さく、上は炎の高さまで。足元基準でアンプの下端 `amp.y`)。下の格子の台は見た目だけ。アンプは中段コンベアの中央のすき間をほぼ埋めているので、中段コンベアの端から中央へ進むと、落ちる前にアンプに触れて炎上する。
- **ベルトコンベア**(仕掛け `conveyors`): 速さは `config.conveyor.speed`(0.5px/ステップ。歩く 1.4 に足し引きされ、逆らうと 0.9・沿うと 1.9)。中段の左右(`c2l` / `c2r`)はアンプの方へ流れたまま、下段(`c1`)は 480 ステップ・最上段(`c3`)は 360 ステップごとに向きが逆転し、逆転の `warnFrames`(60 ステップ)前から両端の滑車が黄色く点滅する。地上で乗っている主人公を `player.carry` で運び、端まで行くと落ちる(段の間隔が大きいのでミス)。ハシゴの上と空中では運ばない。足音は自分で歩いたときだけ。実行時の向き・経過は鉄骨(レベルの中のコピー)の `convDir` / `convTimer` / `vx` / `convWarn` / `beltOffset` に持ち、ステージデータは書き換えない(ミスすると最初の向きに戻る)。描画はベルトの継ぎ目が `beltOffset` ぶん流れ、滑車の軸の点が回る。
- 見た目: 鉄骨は錆びた茶色(ステージデータの `girderColors`。指定のない 1 面はピンク)。中段コンベアの中央のすき間に「爆音アンプ」(ステージデータの `amp`。ドット絵 `amp` + 下から中段の足場まで届く格子の台 + 上で揺らめく黄・オレンジ・赤の炎。炎は `renderer.js` の `drawAmpFlames` が 5 ステップごとに柱の高さを変えて描く)。敵の生成・攻撃はまだない。

### ファイヤースカル(2 面の敵。`js/skulls.js`、仕掛け `fireSkulls`)

- **見た目**: 白いドクロに、銀の鋲と左右のトゲが付いた赤いバンダナ(ドット絵 `skull`)。後ろで青白い炎が揺らめく(`drawSkullFlame`)。当たり判定はドクロの部分だけ(`config.skull` の 14x12px)で炎は含めない。
- **状態**: `emerge`(爆音アンプの炎の中からせり上がる。`emergeFrames` = 30 ステップ)→ `leap`(弧を描いて左右どちらかの中段コンベアへ飛び出す。`leapFrames` = 24・弧の高さ `leapHeight` = 30px)→ `walk`(足場を左右に)⇔ `ladder`(ハシゴを上下に)。`spawn` はテスト補助 `spawnSkull` で直接出したときの「その場に現れる」演出。`emerge` / `leap` / `spawn` の間と着地のときの重なりが解けるまで(`landGrace`)は主人公との当たり判定がなく(`skulls.isHarmless`)、アンプを通り抜けるのもこの間だけ。`emerge` / `spawn` の間は釘バットも届かない。
- **移動**: 速さは `speed`(0.9px/ステップ。コンベアの上ではベルトの速さを足し引きして、沿うと 1.4・逆らうと 0.4)、ハシゴは `climbSpeed`(0.6)。足場の端の `edgeMargin`(8px)手前で折り返すので落ちない。アンプの当たり判定に重なる手前でも折り返す。コンベアの上ではベルトの速さ `g.vx` を足す(それでも端からは出ない)。通りかかったハシゴを `ladderChance`(20%)で使い、主人公がいる段の方向なら `chaseChance`(70%)(`skulls.ladderChanceFor`)。左右の向きは `thinkInterval`(60 ステップ = 1 秒)ごとに考え直す(`skulls.thinkDir`): 主人公と同じ段なら `sameLevelChase`(70%)で主人公の方・残りは逆、違う段なら `wanderChance`(15%)で気まぐれに反対。ハシゴを降りた(登った)直後も、その段に主人公がいれば 70% で主人公の方、いなければ左右半々。完全には追わない(ときどき逆へ行く)。`noHazard`(ガールの足場へのハシゴ)と切れたハシゴは使わない。
- **安全地帯**: 主人公がつかまっているハシゴには入らない。そのハシゴの上下の足場では、ハシゴから `playerWall`(20px)より近づく向きに進まない。ハシゴの途中で主人公が同じハシゴにつかまったら、主人公から離れる向きへ引き返す。
- **出現**: 必ず爆音アンプから。出現のときはアンプの赤・オレンジ・黄の炎が噴き上がる(見た目だけ。当たり判定 `config.amp` は変えない)。`level.ampFlare` が残りステップ(現れる + 飛び出すの 54 ステップ)で、大きさは `DP.mechanics.amp.flameScale` が決める: 最初の `flareRise`(6)ステップで最大 `flareScale`(3.5 倍)まで一気に噴き上がり、現れる間は最大のまま、飛び出している間に元に戻る。最大のときは炎の柱が 16 本 → 22 本に広がり、揺らめきが速くなって火の粉が上へ飛ぶ。飛び出す側はステージデータの `skulls.landings`(左 `c2l` の x=200・右 `c2r` の x=280。どちらもアンプの当たり判定に触れない位置)から、主人公の位置に関係なく左右 50% のランダム(`skulls.pickLanding`)。着地したらアンプから離れる向きへ通常の移動を始める。着地した瞬間に主人公と重なっていたら、理不尽な即死を防ぐため、重なりが解けるまで当たらない(`landGrace`。スカルが動いたあとに毎ステップ確かめ、離れたら通常の当たり判定に戻る)。最初はプレイ開始から `firstSpawn`(60 ステップ = 1 秒。READY の間は数えない)、そのあと `spawnInterval`(120 ステップ = 2 秒)ごと。同時に `maxAlive`(3)体まで、周回ごとに +1(最大 `maxAliveCap` = 5)。出現の経過はレベルに持つので、ミスすると数え直し。
- **主人公との接触**: スカルは `burns: true` なので、触れると炎上のミス(アンプと同じ演出)。判定はビールのすぐあと、すべての敵(`g.enemies`)に共通の処理として `game.js` が行う。
- **釘バット**: 倒すと 500 点(`score.skull`)と破壊音。ドクロが白い骨のかけらになって飛び散り、青い炎がしぼんで消える(`effects` の `type: 'skull'`)。
- ミス・クリアの逃走演出の開始時には、敵は片付く。

### 音(すべて `audio.js` で Web Audio API により合成。音源ファイルは使わない)

- **ミュート**: M キーで ON/OFF。OFF の間は効果音も BGM も鳴らさない(設定は `localStorage` に保存)。
- **歩く足音**: `player.update()` が地上で実際に動いたときだけイベント `ev.step`(`'stepA'`=ピコ / `'stepB'`=ポコ)を返し、`game.js` が鳴らす。間隔は `config.player.stepInterval`(12 ステップ)。ハシゴ・空中、釘バット使用中(釘バットの BGM が流れているため)は鳴らさない。通常の BGM の間は鳴らす。
- **通常プレイの BGM**(`'main'`。全ステージ・全周回で共通の 1 曲。試作版): 曲データは `js/music.js` の `SONGS`、流す曲は `MAIN_SONG`。
  - 今の曲 `oneTwo`: Tom And Boot Boys「1,2, Song」(ユーザーのバンドの曲)の**コード進行だけ**を使ったファミコン風オリジナルアレンジ。メロディー・リズム・ベースラインは新しく作ったもの。コード進行は MP3 の音の成分から推定したもので、正確な採譜ではない(キー B。歌の部分 B → F# を 2 拍ずつ、盛り上がる部分 E → C#m → E → F#)。
  - 150 BPM・12 小節(19.2 秒)ループ。イントロ 2 小節(12.5% の細い矩形波で 16 分のピコピコ分散和音)→ A メロ 4 小節(裏拍のギターのカッティング + ギャロップのベース + 16 分のハイハット)→ サビ 4 小節(E → C#m → E → F#。「ワン・ツー!」と 2 回たたいてから答えるメロディー、4 つ打ちのキック)→ ブレイク 2 小節(16 分の下降リフ → スネアの連打で頭へ)。
  - 前の試作版と「キーが違うだけ」に聞こえないよう、リズムの型・伴奏・音色・メロディーのリズムを変えてある(テスト M9 で確認)。一度、伴奏の型が試作版とまったく同じだったため「曲が変わっていない」と聞こえる問題があった。
  - 前の試作版(E のキー、仮のオリジナル)は `SONGS.proto` に残してある。`MAIN_SONG = 'proto'` で戻せる。曲を差し替えるときは同じ形の曲データを足して `MAIN_SONG` を変えるだけ(`audio.js` は変えなくてよい)。
  - ファミコンと同じ 4 チャンネル: 矩形波 1(デューティ比 50%。メロディー、のばす音にビブラート)/ 矩形波 2(25%。パワーコードを 16 分の分散和音・8 分の刻み)/ 三角波(8 分刻みのベースと、音程を急降下させるキック。同時に 1 音だけ)/ 雑音(スネア・ハイハット・クラッシュ)。25% の矩形波は `createPeriodicWave` で作る。
  - `audio.js` の `SONGS.main` が `DP.music.events()` の音を予約して鳴らす(釘バットの BGM と同じ予約方式・ダッキング・M キーの扱い)。BGM 全体の音量 `gain: 0.75` で効果音より控えめ。タブが裏に回ってタイマーが遅れても、過ぎた音はまとめて鳴らさず今の時刻から続ける。
  - `updateMusic()`: READY(ゲーム開始・各面の開始・ミス後)とプレイ中は `'main'`、釘バット所持中は `'bat'` を優先し、時間切れで `'main'` に戻る(頭から)。ミス(dying)・逃走演出・クリア・ゲームオーバー・タイトルでは止める。面の切り替えでは逃走演出で一度止まるので 2 曲が重ならない。足音は今までどおり(釘バット使用中以外は鳴る)。
  - ブラウザの音声再生の制限: 最初のキー入力・クリック・タッチで `AudioContext` を作って再開する(`audio.js` の `unlock`)。
  - テストは `tests/music.spec.js`(M1〜M9)。テスト補助: `musicActive()`(流れている BGM の数)/ `audioState()` / `recordMusicSteps()`・`musicSteps()`・`seekMusic(step)`(ループのつなぎ目の確認)。
- **釘バットの BGM**(オリジナル曲 `BAT_SONG`: テンポ 168、Em→C→D→B の 4 小節ループ。矩形波メロディー + 三角波ベース + 雑音スネア): `game.js` の `updateMusic()` が毎ステップの最後と逃走演出の開始時に「プレイ中かつバット所持中」かを見て `DP.audio.setMusic('bat' | null)` を呼ぶので、時間切れ・ミス・クリアで自動的に止まる。音 OFF の間は流さず、ON に戻したときまだ所持中なら再開する。少し先まで音を予約しておき 40ms ごとに続きを足す方式で、止めるときは BGM 専用の GainNode ごと切り離す。取得音・破壊音・警告音・終了音は BGM と同時に鳴らす。
- **釘バットの破壊音** `smash`(「ビュイ～～ン!」。`zap`): 約 0.5 秒で 1760Hz → 140Hz へ指数カーブで下げる矩形波 + 1 オクターブ下の三角波に、22Hz のビブラートをかける。BGM 中でも聞こえるよう大きめに鳴らし、鳴っている間は BGM の音量を 3 割に下げる(`duckMusic`)。得点表示と同じステップで鳴る。
- **逃走演出の音**: 歩き・足踏みのたびに足音(`bossStep` / `bossStep2`。矩形波を 180Hz → 60Hz へ急降下 + 雑音)、担ぎ上げる瞬間に悲鳴(`scream`)、手をかけ替えるたびに登る音(`climb`。登った段数ぶん半音ずつ高くなる)、終わったらクリアジングル。
- **低い音の注意**: ノート PC などの小さなスピーカーは約 150Hz 以下をほとんど鳴らせない。低い音を作るときは、倍音の多い矩形波にしたり高めの成分から始めたりして、聞こえる成分を含めること。

## ステージを追加するとき

1. `js/stages/stage3.js` などを作り、`DP.stages.push({...})` で登録する(`index.html` の読み込みも追加)。面の仕掛けが必要なら `js/mechanics.js` に登録し、ステージデータの `mechanics` に名前を書く。
2. ベルトコンベア・エレベーター・リベットなど新しい地形は、ステージデータ(鉄骨の `kind` や新しい種類のデータ)に書き、`geometry.buildLevel` で実行時オブジェクトにして、毎ステップの更新は `js/mechanics.js` の仕掛けとして登録する(`game.js` に面ごとの処理を直接書かない)。プレイヤーや障害物の着地判定は `geometry` / `physics` にまとめる。
3. 周回の難易度は `game.js` の `difficulty()` で調整する。

## 実装ルール

- ハイスコアは `localStorage` のキー `pachiDonkey.highScore`、音の設定は `pachiDonkey.sound`(`'on'`/`'off'`)。プロジェクト名変更前の名前だが、変えると保存済みのデータが消えるのでそのままにする。
- ドット絵の見た目を変えても当たり判定は変わらない。見た目に合わせた高さの数値(`brokenLadder.headroom`、`bat.itemFloat` など)は、主人公のドット絵の高さを変えたら見直すこと。
